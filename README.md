# docstruct

**发出去之前，先让结构对得上。**

`docstruct` 检查 Markdown 文档的结构问题：标题层级是否跳级、编号是否断档、
有没有正文过短的空章节、有没有残留的占位符。

- 零依赖，Python 3.10+ 标准库即可运行
- 单文件，`docstruct.py` 拷走就能用
- 只做机械判定，不评价措辞与观点

## 安装

零依赖，Python 3.10+ 即可：

```bash
pip install shan409279-docstruct
```

装完直接用命令名调用：

```bash
docstruct --help
```

也可以不用安装，直接把 `docstruct.py` 拷走用——它只依赖标准库。

## 为什么需要它

内容写得再好，结构有毛病的话读者还是读不下去。最常见的几种：

- **标题跳级**——正文里从 `##` 直接写到 `####`，生成目录之后才发现
- **编号断档**——`3.2` 后面接的是 `3.4`，读者以为漏了一节
- **空章节**——标题下面只有一句「待补充」，甚至什么都没有
- **占位符残留**——`<待补充>`、`TODO` 直接跟着文档发了出去

`docstruct` 只回答一个问题：**这份文档的结构立得住吗。**
它不评价你的措辞好不好，也不评价你的观点对不对——那些需要人来判断。

## 用法

```bash
python docstruct.py --file README.md

# 机器可读输出
python docstruct.py --file README.md --json

# 只看目录结构
python docstruct.py --file README.md --outline
```

输出：

```
文件：README.md
行数：128，标题数：14

发现 3 处结构问题：
  行    24  [level_jump] 标题层级从 h2 跳到 h4
          上一节「安装」在第 18 行，本节「深入配置」在第 24 行；若确为有意的分层，需人工确认
  行    57  [number_gap] 编号不连续：3.2 → 3.4
          第 51 行的编号与第 57 行之间有跳号，读者可能以为漏了内容
  行    92  [placeholder] 残留占位符：待补充占位符
          第 92 行包含 '<待补充>'

分类统计：level_jump 1、number_gap 1、placeholder 1

说明：本工具只做机械判定。「空章节」阈值可按文档体量自行调整；
「编号断档」只在同一编号体系内比较，跨体系不报。
```

退出码：有问题时为 `1`，通过时为 `0`，文件读不到时为 `2`——
可以直接挂进 CI 当门禁。

## 检查的四类问题

### 标题层级跳级

相邻两个标题之间，层级不能跨过一级。`h2` → `h4` 会报出来；
`h3` → `h2`（往上走）不报，那是正常的。

报告里会附上前后两个标题的位置，方便你直接跳过去。

### 编号断档

只比较**同一编号体系**里的标题：`1.1` 后面接 `1.2` 没问题，
`1.1` 后面接 `1.3` 会报；`1.1` 后面接 `2.1` 属于不同体系，不报。

识别的编号写法：`1.` `1.1` `1.1.1`、`一、`、`第一章`。

### 空章节

一个标题下面直属正文少于 40 个字符就标出来。**只算直属正文**——
如果下面还有子标题，子标题的内容不计入这一节的正文长度。

这个阈值是固定的默认值，不同体量的文档需要自己权衡。

### 占位符残留

检查 `<待补充>`、`<待核验>`、`<待填写>`、`TODO`、`FIXME`、`XXX`、
以及「待补充」「占位」等中文残留标记。

**代码块里的内容会被跳过**——示例代码里写 `TODO` 是正常的。

## 已知局限

- **只处理 Markdown**，不解析 reStructuredText、AsciiDoc 或 HTML。
- **不检查表格与图片的引用**，图片链接失效、表格列数不齐这类问题它不管。
- **不检查重复标题**。两节同名不会被报出来。
- **不判断空章节是不是故意的**。有些章节就是一句话（版权声明、变更日志），工具会照报，需要你人工确认。
- **不做语义上的结构建议**。它不会告诉你「这里应该拆成两节」。
- **标题里的编号要写在标题行内**（`## 1.1 概述`），用 HTML 写的编号识别不到。

## 为什么还要做这个

Markdown linter 已经有不少，但它们大多按一套固定风格来要求文档——
标题必须用 ATX 风格、行宽不能超过 80 列、列表符号必须统一。

`docstruct` 的取向不同：**只查那些真的会妨碍阅读的结构问题**，
不查风格偏好。风格问题交给编辑器插件和格式化工具去管，
这里专门盯住「读者会因为结构卡住」的那几件事。
